# Agent Shopper

A conversational shopping search & recommendation agent built for the
**TechJam 2026 "Shopping Copilot" challenge**. It finds one target product
out of a 50,000-item Amazon `Clothing_Shoes_and_Jewelry` catalog through up
to 10 turns of natural-language dialogue, combining dual-track intent
routing, multi-route retrieval, a slot-accumulation + intent-override
dialog state machine, and adaptive, context-distilled orchestration.

This repository forks the official
[`techjam-conversational-search`](https://github.com/TechJam2026/techjam-conversational-search)
participant kit. The competition harness (`evaluator/`, `data/`, `docs/`) is
unmodified; the full agent implementation lives in
[`agent_shopper/`](agent_shopper/), wired in through
[`starter/agent.py`](starter/agent.py).

## Results at a glance

| | Hit Rate@10 | MRR | MTTC | TechnicalScore |
|---|---|---|---|---|
| Organizer baseline (stock weak-BM25) | 0.125 | 0.068 | 9.81 | 0.107 |
| **Agent Shopper (shipped default)** | **0.705** | **0.439** | **5.27** | **0.599** |

A ~5.6x Hit Rate@10 and ~6.5x MRR improvement over the baseline on the
200-session public dev set, with no paid LLM call required — the shipped
default is entirely local/free (see "LLM usage" below). Full progression,
per-scenario breakdown, and the evidence behind every step: see
["Results on the public dev set"](#results-on-the-public-dev-set-200-sessions)
below and [`docs/experiments.md`](docs/experiments.md).

## How this addresses the problem statement

The brief calls for four pillars; each maps to a small set of modules.

| Pillar | What it means here | Modules |
|---|---|---|
| **I. Intent Routing & Hybrid Pipeline** | Each turn is scored on language decisiveness and slot specification, combined with hysteresis so the track doesn't flip on a marginal change. Buying hard-gates retrieval to a structured filter once enough slots are known; a hard-requirement slot ("must be leather") is enforced immediately even on browsing. Three routes (BM25, category filter, TF-IDF vector) are fused by weighted RRF, then reranked by a pluggable heuristic-or-LLM stage. A frozen local cross-encoder reranking stage is enabled by default (see "Frozen cross-encoder reranking" below). | [`intent.py`](agent_shopper/intent.py), [`bm25_index.py`](agent_shopper/bm25_index.py), [`tfidf_index.py`](agent_shopper/tfidf_index.py), [`category_index.py`](agent_shopper/category_index.py), [`retrieval.py`](agent_shopper/retrieval.py), [`reranker.py`](agent_shopper/reranker.py), [`cross_encoder_reranker.py`](agent_shopper/cross_encoder_reranker.py) |
| **II. Multi-Turn Scenario Evolution** | A `SessionState` accumulates slots (category/material/color/size/style/brand/budget/feature/use_case) turn by turn, distinguishing plain accumulation from an Intent Override (contradiction language, conflicting category, or non-overlapping budget) that clears and rewrites affected slots. A same-department category swap keeps style/feature; a cross-department one clears them. Hard-requirement slots are relaxed last. Letter clothing sizes and numeric shoe/waist sizes are never merged. An over-general pool triggers an information-gain clarifying question while still returning a best-effort recommendation that turn. | [`slots.py`](agent_shopper/slots.py), [`dialog_state.py`](agent_shopper/dialog_state.py), [`dialog_policy.py`](agent_shopper/dialog_policy.py) |
| **III. Dynamic Context Programming** | The harness's `reset()` `user_profile` is distilled once into soft priors (decisiveness, preference-tag boost, rating-floor hint). Session slots and shown-item history are distilled every turn into a bounded representation, which also drives a soft repeat-penalty against re-surfacing shown, unconverted items. A small decision-table orchestrator re-selects routing/reranking/clarification strategy at runtime based on turn budget, pool size, and progress. | [`context.py`](agent_shopper/context.py), [`orchestrator.py`](agent_shopper/orchestrator.py) |
| **IV. Evaluation** | Scored against the official `evaluator/local_evaluator.py` (Hit Rate@10, MRR, MTTC, TechnicalScore) on the 200-session public dev set. Every tunable in `config.py` was validated this way before being locked in — see [`docs/experiments.md`](docs/experiments.md) for the specific before/after numbers. | [`scripts/run_local_eval.py`](scripts/run_local_eval.py) |

The full per-turn algorithm lives in `dialog_policy.process_turn`;
`agent.py` is intentionally a thin `reset()`/`respond()` shim over it.

## How this was validated

- Every `config.py` default was validated by an A/B run of the official
  local evaluator before being locked in, and refit/re-validated by
  stratified k-fold CV for anything with enough free parameters to overfit
  200 sessions (e.g. the learned reranker weights, the override-probability
  model).
- A negative result is reverted in full, not kept as a disabled toggle — of
  21 changes attempted, close to half regressed or measured neutral and
  were removed completely, dead code included.
- A local model artifact goes through offline replay and CV before it's
  enabled by default, then a fault-injected circuit-breaker test and a full
  re-evaluation against the *extracted submission archive itself* — the
  path the frozen cross-encoder took.
- Working theories are corrected by direct measurement, not left standing
  on inference (e.g. a feature-contribution trace overturned an initial
  guess about why a class of misses couldn't recover).
- A shipped regression is caught and rolled back the same way it was
  validated in (e.g. a hard-constraint regex was tightened after a
  bisected eval run showed it firing on the simulator's own scripted
  phrasing).

Full experiment-by-experiment ledger, with eval numbers for every attempt
(shipped and reverted): [`docs/experiments.md`](docs/experiments.md).

### LLM usage: pluggable and optional

A paid LLM is **not required**. The pipeline runs entirely free/local by
default — hand-rolled BM25, TF-IDF/cosine, rule-based intent & slot
extraction, and a weighted heuristic reranker. If `OPENAI_API_KEY` or
`ANTHROPIC_API_KEY` is set, the semantic-ranking stage upgrades to a real
LLM judge call (`reranker.LLMReranker`), with automatic fallback to the
heuristic path on failure, a circuit breaker after repeated failures, and
the last turn always using the fast local path. Force the free path
explicitly with `AGENT_SHOPPER_FORCE_HEURISTIC=1`. Every turn's `usage`
field is real token counts read off the provider SDK's response object,
never a stub — this is what `scripts/estimate_llm_cost.py` aggregates into
the cost projection. (The LLM reranker path was benchmarked and found to
regress vs. the heuristic default due to candidate-order sensitivity — see
`docs/experiments.md`.)

### Frozen cross-encoder reranking: validated, shipped as the default

`agent_shopper/cross_encoder_reranker.py` adds a small, entirely local,
frozen (`.eval()` + `requires_grad_(False)`, `torch.inference_mode()`)
pointwise cross-encoder (`cross-encoder/ms-marco-TinyBERT-L-6`), fused with
the existing heuristic by weighted RRF over a K=100 hybrid candidate union.
Because it scores each query-candidate pair independently, it avoids the
listwise LLM reranker's candidate-order sensitivity. Enabled by default
(`AGENT_SHOPPER_FROZEN_CROSS_ENCODER=0` to opt out and reproduce the 0.5674
heuristic-only baseline); loads a packaged, self-contained checkpoint from
`models/cross_encoder/ms-marco-TinyBERT-L-6/` fully offline — a judge's run
needs zero `AGENT_SHOPPER_*`/`HF_*` environment variables.

Validated via: offline replay + candidate-order-invariance tests, 5-fold
CV (mean TechnicalScore delta +0.0315, zero hit→miss flips across folds),
a fault-injected circuit-breaker test, and a full 200-session re-run
against the extracted submission archive (bit-exact reproduction:
HitRate@10 0.705, MRR 0.439224, MTTC 5.27, TechnicalScore 0.598867).
Organizer policy on timeouts, archive size, and checkpoint bundling has
since been resolved in the project's favor (no per-response timeout, no
package-size limit, checkpoint bundling explicitly allowed).

Full model-identity provenance, packaging method, stability/latency
measurements, and archive verification steps:
[`docs/deployment_notes.md`](docs/deployment_notes.md).

## Setup and installation

Produced with Python 3.13.7, macOS (Apple M1, CPU only), `torch` 2.11.0,
`sentence-transformers` 6.0.0, `scikit-learn` 1.7.1, `numpy` 2.3.2 — see
`docs/deployment_notes.md` for hardware-specific latency numbers. No
pinned Python version is required, but pre-3.10 is untested.

```bash
git clone <this-repo-url> agent-shopper
cd agent-shopper
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Catalog is distributed separately (not committed) -- download + verify:
curl -L -o data/catalog.jsonl.gz \
  https://github.com/TechJam2026/techjam-conversational-search/releases/download/participant-kit/catalog.jsonl.gz
curl -L -o data/SHA256SUMS \
  https://github.com/TechJam2026/techjam-conversational-search/releases/download/participant-kit/SHA256SUMS
(cd data && shasum -a 256 -c <(grep catalog.jsonl.gz SHA256SUMS))
gunzip -k data/catalog.jsonl.gz   # -> data/catalog.jsonl, 50,000 rows
```

Optional, only if you want the LLM-upgraded reranker locally:

```bash
cp .env.example .env   # if present; otherwise just export directly
export OPENAI_API_KEY=sk-...        # or ANTHROPIC_API_KEY=...
```

## Steps to reproduce results

```bash
# Unit tests (agent_shopper's own tests + the kit's own evaluator tests)
python -m unittest discover -p "test_*.py"

# Full local evaluation against the 200-session public dev set
python3 scripts/run_local_eval.py --label "my-run"
# Force the free/local path only (fast, no API cost):
AGENT_SHOPPER_FORCE_HEURISTIC=1 python3 scripts/run_local_eval.py --label "heuristic-only"
```

`scripts/run_local_eval.py` wraps the official `evaluator.local_evaluator`,
prints metrics overall and broken down by `scenario_type` and
`difficulty_bucket`/`category_bucket`, and appends each run to
`eval_runs.jsonl` for comparing tuning iterations.

### Results on the public dev set (200 sessions)

| | Hit Rate@10 | MRR | MTTC | TechnicalScore |
|---|---|---|---|---|
| Organizer baseline (stock weak-BM25) | 0.125 | 0.068 | 9.81 | 0.107 |
| Agent Shopper, heuristic-only (no LLM, no cross-encoder) | 0.675 | 0.410 | 5.66 | 0.567 |
| **Agent Shopper (shipped default, + frozen cross-encoder)** | **0.705** | **0.439** | **5.27** | **0.599** |

Per-scenario Hit Rate@10 (shipped default):

| scenario_type | n | Hit Rate@10 |
|---|---|---|
| buying | 80 | 0.750 |
| browsing | 80 | 0.713 |
| intent_override | 30 | 0.567 |
| boundary | 10 | 0.700 |

`intent_override` still trails the other tracks — it's the deliberately
adversarial track (a preference reversal mid-session) and the smallest
sample (n=30), so a couple of misses move the rate a lot — but it moved
the most of any track across the dense-retrieval addition and a targeted
slot-extraction fix. Re-run `scripts/run_local_eval.py` to reproduce these
numbers; they're logged to `eval_runs.jsonl`, not hand-copied.

The LLM-upgraded reranker path is benchmarked but not shipped as default
(a clean regression vs. the heuristic reranker, root-caused to candidate-
order sensitivity, not prompt injection). Full numbers, the dense-retrieval
addition, the learned-reranker-weights CV, and every other attempted
change (shipped or reverted) are in
[`docs/experiments.md`](docs/experiments.md).

## Development tools, APIs, libraries, and data

- **Dev tools:** Claude Code, standard Python tooling (`venv`, `unittest`).
- **APIs (optional):** OpenAI (Responses API, structured outputs) or
  Anthropic (Messages API) for the LLM reranking stage. No paid API is
  required to run or evaluate the agent.
- **Libraries:** `numpy`, `scikit-learn` (TF-IDF/cosine), `pydantic`
  (structured LLM output schemas), `python-dotenv`; `openai`/`anthropic`
  only imported when a key is present. BM25 is hand-rolled (no
  `rank_bm25` dependency). `sentence-transformers`/`torch` power the dense
  retrieval route and the frozen cross-encoder reranker — both frozen,
  non-fine-tuned encoders, loaded on first use.
- **Data:** the official TechJam frozen catalog (50,000 products from
  Amazon Reviews 2023's `Clothing_Shoes_and_Jewelry` category) and the
  200-session public dev set, both provided by the competition organizer.

## Limitations and what we'd improve with more time

- **26 of 200 public sessions never recall the target from any route at
  any depth.** A direct per-feature contribution measurement found the
  bottleneck is two-layered: a rating-ranked candidate injection never
  surfaces most of these targets in the first place (they aren't highly
  rated), and for the few that are selected, lexical absence (not rating)
  is what loses the reranking. Fixing it needs a different injection-
  selection signal, not a smaller version of what was tried. Full
  diagnostic trail in `docs/experiments.md`.
- **Slot extraction is keyword/regex-based, not learned** — covers a
  hand-curated vocabulary and misses paraphrases outside it. A small local
  NLI or embedding-similarity matcher would generalize better.
- **No negative/exclusion constraint handling** ("no leather") —
  prototyped and measured, removed rather than shipped disabled since it
  has no eval track record either way.
- **Clarify-attribute relevance weighting is a hand-tuned per-department
  table**, not learned from the catalog.
- **The `vector` route is still TF-IDF only**; dense embeddings were added
  as a separate route alongside it rather than replacing it, to keep the
  no-required-download TF-IDF path as a fallback.
- **The dense route's ~245MB embedding cache isn't packaged/committed**
  (only the encoder model is) — a fresh clone pays a one-time ~27-minute
  CPU build, though it no longer needs network access to start.
- **No browsing-track diversity pass** — the competition's TechnicalScore
  has no diversity term, so this wouldn't be scored; worth adding for a
  real deployment.
- **Constraint strength is inferred from a hand-curated regex**, not a
  learned classifier, and deliberately excludes phrasing that matches the
  simulator's own scripted turn-1 message (a bisected eval run showed
  including it regressed buying Hit Rate@10 from 0.51 to 0.41).
- **Clarify-attribute selection uses fixed price/vocabulary buckets**, not
  a fully general entropy calculation.
- **LLM reranking is at most one call per turn**, skipped on clarifying-
  question turns, with candidate text explicitly marked untrusted in the
  prompt.
- **No cross-session personalization** beyond the harness's own `reset()`
  profile — the competition defines each session as isolated, so this is a
  scope decision, not an oversight.
